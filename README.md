# Тихий Час — Telegram-бот (MVP-пилот)

Рабочий бот гостевого флоу: лента тихих окон, бронирование с QR-кодом,
«Мои брони» с отменой, «Тихие баллы» с рефералкой, анкета подключения
заведения и админка подтверждения визитов. Открывает наш Mini App кнопкой.

## Запуск за 10 минут

1. **Токен.** В Telegram откройте @BotFather → `/newbot` → имя и @username
   → скопируйте токен.
2. **Настройка.**
   ```bash
   cp .env.example .env      # вставьте BOT_TOKEN и свой Telegram ID в ADMIN_IDS
   ```
   Свой ID можно узнать у @userinfobot.
3. **Установка и старт** (Python 3.11+):
   ```bash
   pip install -r requirements.txt
   python -m app.main
   ```
4. Напишите боту `/start`. Готово.

## Mini App

Разместите `tihiy-chas-miniapp-v2.html` на любом HTTPS-хостинге
(Vercel/GitHub Pages/своём) и впишите ссылку в `MINIAPP_URL` в `.env` —
у бота появится кнопка «▶️ Открыть приложение» и меню-кнопка чата.

## Админка

- `/admin` — список команд
- `/leads` — заявки заведений
- `/visit ТЧ-1234` — подтвердить визит по коду брони: гостю начислятся
  баллы (10, ×2 за первое посещение заведения), придёт уведомление.
  На проде это заменит скан QR в кабинете заведения.

## Структура

```
app/
  config.py        # .env: токен, админы, депозит 149 ₽, баллы
  db.py            # SQLAlchemy 2.0 async: users/venues/slots/bookings/leads/ledger
  seed.py          # 9 пилотных заведений Петроградки
  keyboards.py     # инлайн-клавиатуры и callback-фабрики
  handlers/guest.py    # /start (+deep-link рефералка), лента, бронь+QR, брони, баллы
  handlers/partner.py  # анкета заведения (FSM), админ-команды
  main.py          # bootstrap: бот, роутеры, меню-кнопка Mini App

```

## Продакшен-заметки

- **PostgreSQL**: поменяйте `DB_URL` на
  `postgresql+asyncpg://user:pass@host/db` и добавьте `asyncpg` в requirements.
- **Платежи (депозит 149 ₽)**: точка врезки — `handlers/guest.py: book()`.
  Вместо мгновенного создания брони создаём платёж ЮKassa/Т-Касса
  (сплит + чек 54-ФЗ с признаком агента), бронь активируется вебхуком
  об успешной оплате. Сейчас пилот работает без денег — брони бесплатные.
- **Напоминания за 2 часа**: добавить APScheduler-задачу по `bookings`.
- Хостинг — РФ (152-ФЗ): Yandex Cloud / VK Cloud / Selectel.

## API для формы на сайте

Приём заявок партнёров с сайта живёт в `app/api.py` и пишет в ту же базу,
что и бот (таблица `partner_leads`), плюс шлёт уведомление админам в Telegram.

Запуск рядом с ботом:
```bash
.venv/bin/uvicorn app.api:api --host 0.0.0.0 --port 8080
```

Настройте в `.env` разрешённые домены сайта:
```
CORS_ORIGINS=https://tihiychas.ru,https://tihiy-chas.vercel.app
```

На проде обязательно за nginx с HTTPS — браузер не пустит запрос
с https-сайта на http-адрес. После деплоя впишите адрес в `API_URL`
в файле сайта (строка рядом с `const BOT =`).

Защита: honeypot-поле, лимит 5 заявок с IP за 10 минут, валидация телефона.

## Кабинет партнёра (этап 1)

Вход — через Telegram Mini App, без паролей и SMS. Telegram передаёт
подписанную строку `initData`, мы проверяем её HMAC-подписью ключа бота
(`app/auth.py`) и точно знаем, кто открыл кабинет.

**Решения проекта:** вход только через Telegram · один кабинет на организацию,
точек внутри может быть несколько · визит подтверждает хостес или официант
со своего телефона · модерация пока на одном человеке.

### Эндпоинты

```
POST /api/cab/login    {init_data, invite?}   вход владельца или сотрудника
GET  /api/cab/me                              профиль и организация
POST /api/cab/invites  {role}                 владелец создаёт приглашение
GET  /api/cab/staff                           список сотрудников
```

Все запросы, кроме `login`, требуют заголовок `X-Init-Data` с той же
подписанной строкой от Telegram.

### Как подключить первого партнёра вручную

Пока нет экрана модерации, партнёр заводится напрямую в базе:
организация в `partners`, владелец в `partner_users` с его Telegram ID
и ролью `owner`. Дальше владелец сам приглашает хостес ссылкой из кабинета.

### Проверено тестами

Подделка подписи, чужой токен, устаревшие данные, вход без приглашения,
повторное использование приглашения, попытка сотрудника пригласить
другого — всё отклоняется.

## Синхронизация с сайтом (важное обновление)

Бот приведён в полное соответствие с сайтом (`tihiy-chas-v10.html`):

- **Депозит и комиссия — единая ставка 99 ₽** (было 149 ₽ депозит и 99/149 ₽
  комиссия по категориям). Правится в одном месте: `app/config.py`.
- **Бронь на любой день из ближайших 14**, а не только «на сегодня». Гость
  сначала выбирает день, затем район и категорию — так же, как в полосе дат
  и селекторе района на сайте.
- **15 районов Санкт-Петербурга**, 34 заведения с собственным расписанием
  дней недели (рестораны — будни, мойки и салоны — включая субботу,
  кофейни/СПА — вся неделя). Сегодняшние прошедшие часы не предлагаются,
  как и на сайте.
- **Текст QR-подтверждения** обновлён: «за вами закрепят столик и отметят
  визит в системе» — без формулировок про рассадку, которые звучали грубо.

### Проверено тестами

`test_smoke.py` — данные и бизнес-логика (депозит/комиссия, 34 заведения,
15 районов, работа расписания по дням недели, бронь на будущую дату, отмена
считает часы от даты визита, а не от «сейчас»).

`test_scenario.py` — **полный сценарий гостя через настоящие хендлеры бота**:
выбор дня → района → категории → карточка заведения → бронь на послезавтра →
QR с новым текстом → отображение даты в «Моих бронях». Ничего не мокается,
кроме самого Telegram API — вся бизнес-логика реальная.

```bash
PYTHONPATH=. python3 test_smoke.py
PYTHONPATH=. python3 test_scenario.py
```

## Кабинет партнёра — этап 2: онбординг заведения

Партнёр сам заводит заведение через мини-апп (`tihiy-chas-cabinet.html`):
карточка → фото → тихие часы → отправка на модерацию. Ничего не публикуется
без ручного решения администратора — это защита от фиктивных заведений
в ленте, которую мы обсуждали с самого начала.

### Новые эндпоинты (`app/cabinet.py`)

```
GET    /api/cab/venues                        список своих заведений
POST   /api/cab/venues                        шаг 1: создать черновик
GET    /api/cab/venues/{id}                    карточка целиком
PATCH  /api/cab/venues/{id}                    шаг 1: редактировать
POST   /api/cab/venues/{id}/photos             шаг 2: добавить фото (base64, до 1.5 МБ, до 5 шт.)
DELETE /api/cab/venues/{id}/photos/{photo_id}  удалить фото
PUT    /api/cab/venues/{id}/quiet-hours        шаг 3: дни недели × часы × скидка
POST   /api/cab/venues/{id}/submit             шаг 4: отправить на модерацию
```

### Модерация (`app/handlers/partner.py`)

Администратору приходит карточка заявки с кнопками «✅ Одобрить» / «❌ Отклонить»
прямо в Telegram — решение принимается в один тап.

- **Одобрение** конвертирует черновик (`VenueProfile` + `QuietWindow`) в
  публичные `Venue` + `Slot` — те самые таблицы, которые уже читают сайт,
  бот и мини-апп гостя. Проверено тестом: до одобрения `Venue.active=False`,
  после — `True`, слоты появляются, дни недели выставлены верно.
- **Отклонение** запрашивает у администратора причину текстом и пересылает
  её партнёру — статус заявки возвращается в черновик для доработки.

Команды: `/pending` — очередь на модерации, `/venue_<id>` — карточка
конкретного заведения с теми же кнопками.

### Мини-апп кабинета (`tihiy-chas-cabinet.html`)

Мастер из 4 шагов в той же палитре, что и весь продукт. Работает в двух
режимах:
- **Demo** (`API_URL` пуст) — все действия имитируются локально, весь
  путь кликабелен и виден сразу, без сервера.
- **Боевой** — впишите адрес бэкенда в `API_URL`, и мастер начнёт писать
  в реальную базу через вход по Telegram initData.

### Проверено тестами

`test_cabinet_stage2.py` — два полных сценария через настоящие эндпоинты
FastAPI (не моки):

1. **Одобрение**: создание → чужой аккаунт не видит (403) → отправка без
   фото/часов отклоняется с понятным списком → фото с лимитом размера →
   сетка тихих часов → отправка → повторная отправка блокируется (409) →
   редактирование во время модерации блокируется (409) → администратор
   одобряет → **заведение реально появляется в публичной витрине**
   (`Venue.active=True`, слоты, дни недели) → это подтверждено через ту же
   функцию `venue_weekdays()`, которую использует гостевой сценарий бота.

2. **Отклонение**: администратор запрашивает причину → партнёр получает
   её текстом → статус возвращается в `draft` → партнёр снова может
   редактировать и отправить заявку повторно.

```bash
PYTHONPATH=. python3 test_cabinet_stage2.py
```

## Боевое развёртывание на VPS (бот + API за HTTPS)

Форма регистрации на сайте и кабинет партнёра работают в demo-режиме,
пока `API_URL` не указывает на реальный сервер. Чтобы включить полный
режим, нужен VPS (Ubuntu 22.04) и домен для API — сайту на HTTPS нельзя
обращаться к серверу без HTTPS (браузер блокирует такие запросы).

### Что понадобится
- VPS с IP-адресом (Timeweb Cloud/Selectel/VK Cloud, ~300–500 ₽/мес)
- Домен или поддомен, например `api.tihiychas.ru` (~200–700 ₽/год),
  с A-записью, указывающей на IP сервера

### Разворачивание одной командой

```bash
scp -r tihiy-bot root@ВАШ_IP:/root/
ssh root@ВАШ_IP
cd /root/tihiy-bot
bash deploy/setup.sh api.ваш-домен.ru
```

Скрипт `deploy/setup.sh` сам ставит зависимости, создаёт `.env` из
примера (токен и ID админов нужно вписать вручную), поднимает бота и
API как systemd-сервисы, настраивает nginx и выпускает HTTPS-сертификат
через certbot. Дальше держит оба процесса живыми и поднимает после
падения или перезагрузки сервера.

### Файлы для этого в `deploy/`
- `setup.sh` — единый скрипт первичной настройки
- `tihiybot.service`, `tihiyapi.service` — systemd-юниты бота и API
- `nginx.conf` — реверс-прокси-конфиг (шаблон, домен подставляется скриптом)

### После разворачивания — ещё три коротких шага

1. **Проверить**: `curl https://api.ваш-домен.ru/api/health` должен
   ответить `{"ok":true}`
2. **Вписать реальный адрес сайта в `.env`** на сервере:
   `CORS_ORIGINS=https://ваш-сайт.vercel.app` (без этого браузер
   заблокирует запросы с сайта как чужеродные)
3. **Прописать `API_URL` в двух местах** и передеплоить на Vercel:
   - в `index.html` — форма регистрации партнёра (`const API_URL`)
   - в `tihiy-chas-cabinet.html` — кабинет партнёра (`const API_URL`)

SQLite оставлен как есть — на VPS диск постоянный, данные не теряются
между перезапусками (в отличие от бесплатных serverless-платформ).
Миграция на PostgreSQL актуальна позже, при реальном росте нагрузки,
не как условие запуска.
